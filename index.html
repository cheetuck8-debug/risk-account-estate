riskai — WTD bot

RunningApprove + hold

Withdrawal-risk system built for peak hours: it reads the verification queue and each player's history, applies ~20 risk rules, approves the withdrawals that pass, and holds the ones that match a rule with a risk remark. Never rejects and never pays — payment stays with the payment department.

What it reads

Withdrawal verification queuePending withdrawals per site and currency — order list, risk score, hold decisions. Every few seconds
Player profile & historyDeposits, withdrawals, bets, bonuses, account age, group, changed-by. Per order
Bonus config & bonus reportTitles, unfinished bonuses, bonus-to-deposit share. Per order / periodic
Win/lossToday's player and site totals — daily player limit, daily site budget. Periodic
ReportsPer-site summary and vendor figures for dashboard statistics. Periodic

What it writes

  • Approve — clears a pending withdrawal so it goes to payment; the automatic clearing used at peak hours
  • Hold — POST /manager/payment/holdWithdrawal, status 3, executor "bot account"
  • Remark — POST /manager/member/updateRiskRemark, rule reason next to the player
  • Release auto-verify — removeAutoVerifyWithdrawalExecutor, a human decides instead
Writes run only when allowHoldWrites is true, the site switch is on and the site's hold mode is real. Every call and its answer is appended to data/hold-actions.jsonl.

What it never does

  • Reject, pay or settle a withdrawal or deposit
  • Close or cancel a withdrawal as paid, or move money
  • Change a player's status, VIP level, group or limits
  • Create, edit or delete a bonus, adjustment or promotion
  • Change a back-office setting or back-office user
  • Export player lists in bulk

riskai5 — Exchange Update Bot

Running

Disposes of a player immediately from Telegram: reject the pending withdrawals, transfer the fund back to the main wallet, deactivate the account. The only account in the estate with money-affecting rights, so every action is shown as a preview and only runs after a whitelisted user replies /ok. It never approves, pays or settles.

Where it runs
/opt/urgent-dispose/bot.py
urgent-dispose.service · restarted on boot
Config / login
/opt/urgent-dispose/env → BO_USER=riskai5
mode 600 · fresh sign-in per command and site
Bot
Disposal bot · English only
TG_ALLOWED: 7 IDs, checked per message
Coverage
All 18 sites, one site code per command. Group mode: bot is group admin and deletes messages from any ID outside the whitelist.

What it reads

Status snapshot /statusName, currency, account status, platform and provider balance, on-hold withdrawals, unsettled bet amount, profile remark
Pending withdrawalsStatus 1, 3 and 4 including on-hold, plus the lock holder
Player lookupsearchMember (dcf=false) + getAccountBalanceList existence check

Five writes, all previewed and confirmed first

RejectgetVerifyWithdrawal then rejectAndAdjustWithdrawal — rejects only, never approves
Take backtransferType=0, providerId=-1, takeBackType=1, amount = provider balance. Only when the provider balance is above zero.
DeactivatePlayer status set to inactive
Auto-payout offupdateProfileSetting on Member → Profile Setting — right granted, so auto-payout can be switched off
RemarkupdateRiskRemark — only with the remark keyword; identical text is skipped
Shortcuts: /kill runs switch off auto-payout → reject → take back → deactivate in that order, and accepts the keywords off reject takeback inactive to run fewer. /active sets status=1, or status=1 plus autoVerification=1 with /av.

Safeguards

  • Preview then /ok — pending plans expire after 15 minutes
  • Whitelist of 7 Telegram IDs checked per message; anyone else gets their ID back and nothing runs
  • Unsettled-bet stop — pendBetAmount > 0 blocks the whole disposal
  • Reason rule — from the operator's words first, then the profile; if neither exists the flow aborts
  • Read-back — after each write the order, balance list and profile are read again before success is reported
  • Stops at the first failed step and reports which step and why

What it never does

  • Approve, pay, settle or complete a withdrawal or deposit
  • Reject or hold anything without an explicit /ok from a whitelisted user after a preview
  • Touch a player who has an unsettled bet
  • Continue past a failed step
  • Invent its own reason text
  • Change VIP level, group, limits or any bonus
  • Accept a command from any other Telegram ID

kpi — KPI Dashboard

RunningNo back-office account

The staff performance board. It holds no back-office login of its own: it is fed by uploaded KPI workbooks, Lark attendance, the roster sheet for leave and the riskai2 vendor page, and turns that into per-verifier figures, rank, late / MIA and leave.

Rule-based, automatic: the KPI is calculated from the configured rules, not tallied by hand. The uploaded workbook, Lark attendance and the roster are scored per staff member, per day and per shift; change a rule and the figures recompute on the next build. The source data is read, never edited.

Safeguards

  • Reads no back office — there is no BO session to lose or to lock
  • Scoring is rule-driven: every KPI figure comes from the rules applied to the uploaded data, so the same input always gives the same score
  • Data comes in as files and API pulls; nothing is written back to a back office
  • Staff and rank edits are made by the dashboard's own admin, recorded in the KPI change notes
  • Served over HTTPS on the same VPS as the rest of the estate

What it never does

  • Sign in to a back office, so it cannot approve, hold or reject anything
  • Move or settle money
  • Change a player's status, limits or bonuses
  • Replace the vendor page it reads — that stays riskai2's output
